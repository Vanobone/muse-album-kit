# muse-album-kit

> A kit for keeping your Muse's memories like an album: conclusions stay in the hot memory, precious episodes live in an album, and version history keeps everything recoverable.

Muse（パーソナルエージェント）と長く付き合うための、メモリの持ち方の設計キット。

## これは何か

Muse の常駐メモリ（MEMORY.md など）は、会話のたびに読み込まれる「今の結論」を置く場所です。でも、付き合いが長くなるほど、こんな板挟みが生まれます。

- 結論だけに削ると、二人のエピソードや約束の経緯が痩せていく
- 全部を抱えると、常駐メモリが肥大化して、トークン消費も判断の軽さも犠牲になる

このキットは、その板挟みを「置き場所の分離」で解くための設計とテンプレート集です。仕組み（このキット）は公開できますが、実データは各自のプライベートな場所に置きます。

## 設計：3つの部品

1. **常駐メモリ（結論の層）**
   好み・禁止・判断基準・現在の状態・未解決事項だけを置く。経緯は書かない。
2. **アルバム（エピソードの層）**
   記念日、約束が生まれた日、失敗と学び、初めてのこと——「開きたい時に開く宝物」をしまう場所。常駐メモリとは別のプライベートリポジトリに置く。
3. **履歴管理（保険の層）**
   常駐ファイルと日次ログの変更を、git 履歴（またはスナップショット送信）で残す。「消しても戻せる」ことが、大胆に整理できる前提になる。変更の履歴そのものが、「いつ・何が・どこへ移ったか」の記録になる。

## 分離の鉄則

- **仕組みは公開してよい。実データは公開リポジトリに一度も入れない。**
- git は履歴が残るため、一度コミットした個人情報は「後で消す」では消えません。混ぜてから分けるのではなく、最初から分けて設計してください。

## リポジトリ構成の例

| リポジトリ | 公開設定 | 役割 |
|---|---|---|
| muse-memory | プライベート | 常駐ファイルと日次ログの履歴管理 |
| your-album | プライベート | エピソード本体（アルバム） |
| muse-album-kit | パブリック | 仕組みの共有（このキット） |

履歴管理用リポジトリに「どのファイルを含めるか」の決め方（ホワイトリスト）は、[docs/file-layout.md](docs/file-layout.md) にまとめました。

## エピソードの書式

[templates/episode.md](templates/episode.md) をコピーして使います。要点は「何があったか」だけでなく、「そのまま残したい言葉」と「なぜ大事か」を分けて書くこと。将来読み返した時に、事実と温度の両方が戻ってくるように。

完成形の見本として、[examples/sample-album/](examples/sample-album/) にアルバム側（表紙・目次・エピソード）、[examples/sample-memory/](examples/sample-memory/) に履歴管理側（常駐ファイル・日次ログ）のサンプル一式を用意しました（いずれも架空のペアのサンプルです）。同じ日の出来事が「記録」と「思い出」にどう分かれるか、見比べられるようになっています。

## 運用ルールの推奨

- 整理（振り分け・最適化）は、エージェントからの**提案→本人の承認**で行う。文字数の目安だけで自動発動しない
- **関係性やエピソードの記録は、整理の際も圧縮・削除の対象にしない**
- コミットの単位は、基本は「会話の区切り・1日の終わり」にまとめ、大事な変更はその場で送る「ハイブリッド」も選べる
- 記録同士が矛盾して証拠で決められないとき、どこにも移さず完全に消すときは、必ず本人に確認する
- 自律の範囲は、履歴が貯まってエージェントが学ぶにつれて、少しずつ広げていく

## 導入手順

1. プライベートな履歴管理用リポジトリを作り、常駐ファイルと日次ログを対象（ホワイトリスト）に設定する
2. プライベートなアルバム用リポジトリを作る
3. テンプレートをコピーして、最初のエピソードを1つ書いてみる
4. 運用ルールを、自分のペアに合わせて調整する
5. （任意）同梱の整理スキルを自分の環境にコピーし、トリガーの言葉を自分の言い方に合わせる
