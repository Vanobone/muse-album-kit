# 復元手順

履歴管理を「保険」として機能させるための、過去の版への戻し方です。

## 考え方

- 復元は「過去の版を、現在のファイルに書き戻して、新しい変更として記録する」こと。**履歴そのものは書き換えない**。だから、復元したこと自体も履歴に残る
- 慌てて戻す前に、まず「何が・いつ・どう変わったか」を履歴で確認する

## 手順

1. **戻したい時点を探す**
   コミット履歴を新しい順に見て、コミットメッセージと日時を目印に、戻したい時点のコミットを特定する
2. **当時の内容を取得する**
   そのコミット時点の、対象ファイルの内容を取得する（git 方式なら `git show <commit>:<path>`、スナップショット方式ならリポジトリの読み取り機能でコミットを指定して読む）
3. **現在のファイルを上書きする**
   取得した内容で、手元のファイルを置き換える。ただし、まだ履歴に送っていない変更が手元にある場合は、**先にそちらを送って履歴に残してから**復元する（でないと、その変更が消えて戻せなくなる）
4. **復元として記録する**
   次回の送信で、コミットメッセージに「どの時点へ戻したか」を明記する

## 注意

- 複数ファイルにまたがる復元は、同じコミット時点に揃える。一部だけ戻すと、ファイル同士の整合（例：MEMORY.md と日次ログの対応）がずれることがある
- 復元は取り消せる（復元の前の状態も履歴に残っている）。だからこそ、手順3の「先に送る」を省かないこと
