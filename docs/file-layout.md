# ファイル構成とホワイトリスト

履歴管理用リポジトリ（例：muse-memory）の対象ファイルの決め方です。

## 前提

- リポジトリのルートは、エージェントのホームディレクトリ相当の場所
- 対象は「メモリ関連ファイル」だけに限定する。理由は3つ：
  1. 履歴に残す価値があるのは、毎回読み込まれる常駐ファイルと、その経緯だから
  2. 対象を広げるほど、送ってはいけないもの（認証情報など）が混ざる危険が上がるから
  3. ランタイムが管理する領域は、エージェントが触らない約束だから

## ホワイトリスト（対象に含める）

| パス | 役割 |
|---|---|
| README.md | リポジトリ自身の説明と運用ルール |
| MEMORY.md | 常駐メモリの本体（結論の層） |
| SOUL.md | エージェントの性格・約束 |
| IDENTITY.md | エージェントの名前・雰囲気 |
| USER.md | 本人の情報 |
| AGENTS.md | 仕事の作法 |
| TOOLS.md | 道具のメモ |
| PROACTIVE_PREFERENCES.md | 連絡の好み |
| memory/YYYY-MM-DD.md | 日次ログ（経緯の層） |
| memory/people/ | 人物の記録 |
| memory/groups/ | グループの記録 |
| memory/archive/（任意） | 振り分け・整理の記録置き場 |

※ people/ や groups/ には他者の情報も含まれうるため、このリポジトリは必ずプライベートにします。

## 対象外（絶対に含めない）

| パス | 理由 |
|---|---|
| memory/bank/、memory/index/ | ランタイムが管理する内部データ |
| dreams/ 配下 | 自動で再生成されるため、履歴に残す意味が薄い |
| 認証情報・秘密の設定ファイル（.ssh、各種トークンや鍵を含む設定） | 漏れると取り返しがつかない |
| 上記以外のホーム内ファイル全て | ホワイトリストに無いものは追跡しない |

## 実装の仕方（2通り）

### 1. スナップショット方式

「対象ファイルの一覧（マニフェスト）」が、そのままホワイトリストを兼ねます。一覧に無いファイルは送信されません。新しく対象を増やす時（例：新しい日次ログ）は、一覧に足してから送ります。

### 2. git 方式（.gitignore をホワイトリスト式にする）

すべてを対象外にしてから、許可するものだけを戻す書き方です（サンプル）。

```gitignore
# まず全てを対象外に
/*
!/memory

# 常駐ファイルだけ許可
!/README.md
!/MEMORY.md
!/AGENTS.md
!/SOUL.md
!/USER.md
!/IDENTITY.md
!/TOOLS.md
!/PROACTIVE_PREFERENCES.md

# memory/ の中も選別する
/memory/*
!/memory/*.md
!/memory/people/
!/memory/groups/
/memory/bank/
/memory/index/
```

適用後は `git status` や `git check-ignore` で、意図したファイルだけが対象になっていることを必ず確認してください。
