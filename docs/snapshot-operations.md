# スナップショット方式の運用詳細

git の認証をエージェントに持たせられない環境で、対象ファイルを選んでリポジトリへ送る「スナップショット方式」を運用するための詳細です。

## 部品

- **送信元フォルダ**：対象ファイルの実体がある場所（ホームディレクトリなど）
- **マニフェスト**：対象ファイルのパスの⼀覧。これがホワイトリストを兼ねる（[file-layout.md](file-layout.md) 参照）
- **同期記録**：送信ごとに {リポジトリ, ブランチ, コミットSHA, 対象パス一覧} を残す記録。次回の送信前チェックに使う

## 送信の手順

1. リモートの最新コミットを確認し、同期記録に残した SHA と一致するか見る
2. 一致していたら、対象ファイルを送る（コミットメッセージには変更の要旨を書く）
3. 返ってきた新しいコミット SHA を、同期記録に追記する
4. 代表ファイルを読み直して、意図通り反映されたか検証する

## 競合時の扱い

- 手順1で SHA が一致しなかったら、**送らずに止まる**
- リモート側で何が変わったかを確認し、手元の変更と突き合わせてから送り直す。勝手に上書きしない

## 対象ファイルの追加・削除・改名

- **追加**：マニフェストにパスを足し、次回の送信に含める。同期記録のパス一覧も合わせて更新する
- **削除・改名**：スナップショット方式では自動で伝わらない（リモートに旧ファイルが残る）。必要になったら、その都度どう扱うかを決めて手作業で対処する。メモリ関連ファイルでは滅多に起きないが、起きたら放置しない
